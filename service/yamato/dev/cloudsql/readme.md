# Service Layer — yamato / dev / cloudsql

The Postgres database for the yamato wiki's dev environment — reachable only over
private IP, with its password generated by Terraform and stored in Secret Manager.

## What this state owns

- `sqladmin.googleapis.com` and `secretmanager.googleapis.com` enabled on `iq9-gcp-dev-yamato`.
- `google_sql_database_instance.this` — Postgres 16, `db-f1-micro`, ZONAL (no HA),
  10 GB SSD (autoresize on), daily backups (03:00 UTC, 7 retained, PITR off).
  **Private IP only** (`ipv4_enabled = false`), attached to `iq9-vpc-dev-yamato`
  through the PSA peering the network state created.
- `google_sql_database.this` — the `yamato` database.
- `google_sql_user.app` — the `yamato_app` user with a 32-char generated password.
- A Secret Manager secret `yamato-dev-db-password` + version holding that password.

It does **not** grant anyone access to the secret — the [`../cloudrun/`](../cloudrun/)
state grants its runtime SA `secretAccessor`, so each state owns its own IAM.

## Connectivity model

Cloud Run reaches this instance over **private IP** via the Serverless VPC Access
connector (created in the cloudrun state). The app uses the Cloud SQL connector
with the instance **connection name** — `iq9-gcp-dev-yamato:us-west1:yamato-dev` —
plus the DB name, user, and the password read from Secret Manager. No public IP,
no SQL Auth Proxy over the internet.

## Deterministic name caveat

`instance_name` has **no random suffix** so dependents (cloudrun) can derive the
connection name without reading this state. The trade-off: a Cloud SQL instance
name cannot be reused for ~7 days after deletion. If you `terraform destroy` this
in dev, recreating under the same name will fail until that window passes.

`deletion_protection = true` (module default) — `terraform destroy` will refuse
until you flip it. Intentional: even a dev DB shouldn't vanish by accident.

## Prerequisites

The Foundation Layer network state must be applied first — the PSA peering on
`iq9-vpc-dev-yamato` is what lets this instance get a private IP. See
[`foundation/gcp-networks/yamato/dev/`](../../../../foundation/gcp-networks/yamato/dev/).

## First-time setup

```bash
cd service/yamato/dev/cloudsql/
terraform init
terraform plan    # ~6 resources: 2 APIs, instance, database, user, secret (+version)
terraform apply   # the instance create is the long pole (several minutes)
```

Verify:

```bash
gcloud sql instances describe yamato-dev \
  --project=iq9-gcp-dev-yamato \
  --format='table(name, databaseVersion, settings.tier, ipAddresses[].type)'
```

Expect `ipAddresses` to show only `PRIVATE` (no `PRIMARY`/public address).
